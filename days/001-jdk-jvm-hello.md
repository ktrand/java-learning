# День 1. JDK, JVM и первая программа

## Зачем

В PHP пишешь файл и запускаешь — интерпретатор читает его прямо при запуске. В Java между исходником и запуском есть шаг компиляции, а программа работает внутри виртуальной машины. Сегодня разберёмся, что мы поставили, как код превращается в работающую программу, и решим первые задачи.

## Что мы поставили

**JDK** (Java Development Kit) — набор для разработки:

- `javac` — компилятор: `.java` → `.class`;
- `java` — запускает программу, то есть саму JVM;
- стандартная библиотека — строки, коллекции, файлы, сеть, потоки и т. д.;
- утилиты: `jshell` (консоль, как `php -a`), `javap` (показывает байткод), `jcmd` (подглядывать в живую JVM).

**JVM** (Java Virtual Machine) — виртуальная машина, которая исполняет байткод. Ближайшая аналогия — сам `php`, только исполняет он не исходник, а заранее скомпилированные инструкции.

**Temurin** — одна из сборок OpenJDK (от Adoptium). Язык один, сборщиков много: Oracle, Temurin, Amazon Corretto, Liberica. Разница в поддержке и лицензиях, а не в языке.

**25 — LTS-версия.** Новая Java выходит каждые полгода (март и сентябрь), и раз в два года версия становится LTS с долгой поддержкой: 17, 21, 25. На проде почти всегда LTS.

## Как код становится программой

```
Hello.java  --javac-->  Hello.class (байткод)  --java-->  JVM: интерпретатор + JIT  -->  машинный код
```

- **Байткод** — не машинный код, а инструкции виртуальной машины. Один и тот же `.class` запускается на Windows, Linux и Mac — переносимость обеспечивает JVM.
- JVM сначала байткод интерпретирует, а методы, которые вызываются часто («горячие»), компилирует в машинный код — это **JIT** (just-in-time). Поэтому Java-сервер после старта «разогревается»: первые запросы медленнее, потом быстро.
- PHP-FPM на каждый запрос начинает с чистого листа. Java-сервер — один долгоживущий процесс: объекты живут между запросами. Это сильно повлияет на то, как пишут бэкенд (вернёмся к этому в Spring).
- Ошибки типов находит **компилятор до запуска**. Похоже на PHPStan, только пропустить его нельзя: не скомпилировалось — не запустится.

## Три способа запустить

### 1. Один файл (Java 25)

`sandbox/day01/Hello.java`:

```java
void main() {
    IO.println("Привет, Java!");
    int checks = 3;
    double total = 1250.50;
    IO.println("Чеков: " + checks + ", выручка: " + total);
}
```

```powershell
java sandbox\day01\Hello.java
```

`java` сам компилирует файл в памяти и запускает — `.class` на диске не появляется. Метод `main` без класса и `IO.println` появились в Java 25 — для скриптов и учёбы. В настоящих проектах пишут по-классически.

### 2. Классика: javac + java

`sandbox/day01/HelloClassic.java`:

```java
public class HelloClassic {

    public static void main(String[] args) {
        System.out.println("Привет из классического main!");
        System.out.println("Аргументов: " + args.length);
        for (String arg : args) {
            System.out.println(" - " + arg);
        }
    }
}
```

```powershell
javac -d out sandbox\day01\HelloClassic.java
```

```powershell
java -cp out HelloClassic one two
```

Разберём строку `public static void main(String[] args)`:

- `public` — метод виден снаружи, иначе JVM его не вызовет;
- `static` — метод принадлежит классу, а не объекту: JVM вызывает его, ничего не создавая;
- `void` — ничего не возвращает (код выхода задают через `System.exit(код)`);
- `String[] args` — аргументы командной строки, как `$argv` в PHP.

`System.out.println` — у класса `System` есть статическое поле `out` (поток вывода), у него вызываем метод `println`.

`-cp out` — **classpath**: где JVM искать классы. Похоже на автозагрузку Composer, только без кода — просто список папок и jar-файлов.

### 3. Проект Maven — здесь живут задачи

```
pom.xml               ≈ composer.json: зависимости и настройки сборки
mvnw.cmd              обёртка: сама скачает нужную версию Maven
src/main/java/day01   код (задачи)
src/test/java/day01   тесты к задачам
target/               результат сборки (.class, отчёты), в git не идёт
```

`package day01;` в начале файла — это namespace. Папка обязана совпадать с пакетом: класс `day01.Basics` JVM ищет по пути `day01/Basics.class`. Почти как PSR-4, только здесь это не договорённость, а требование.

## Подсмотреть байткод

```powershell
javap -c -cp out HelloClassic
```

Кусок вывода:

```
public static void main(java.lang.String[]);
  Code:
     0: getstatic     #7    // Field java/lang/System.out:Ljava/io/PrintStream;
     3: ldc           #13   // String Привет из классического main!
     5: invokevirtual #15   // Method java/io/PrintStream.println:(Ljava/lang/String;)V
    ...
    13: invokedynamic #21   // InvokeDynamic makeConcatWithConstants:(I)Ljava/lang/String;
```

Читать байткод уметь не нужно, но полезно знать, что он есть: `getstatic` — взяли `System.out`, `ldc` — положили строку, `invokevirtual` — вызвали `println`. Интересно: склейку строк `"Аргументов: " + args.length` компилятор превратил в `invokedynamic` — JVM сама выбирает, как склеивать быстрее всего.


## Грабли для PHP-шника

1. **`'abc'` — ошибка компиляции.** Одинарные кавычки — один символ (`char`): `'a'`. Строки — только в двойных.
2. **`5 / 2` равно `2`.** Деление целого на целое — целое, дробная часть отбрасывается. В PHP было бы `2.5`.
3. **Тип переменной фиксирован.** `int x = 5;` — дальше в `x` можно класть только `int`. Есть `var x = 5;` — тип выведет компилятор, но он всё равно станет `int` навсегда.
4. **`;` обязательна**, и PHP-шного «последняя строка без точки с запятой» нет.
5. **Имя public-класса = имя файла**, с учётом регистра. Windows регистр файлов прощает, `javac` — нет.
6. **Строки через `==` не сравнивают** — это сравнение ссылок, а не содержимого. Нужен `equals()`. Подробно — в день 6.
7. **Кириллица в терминале превращается в `???`.** Java пишет в консоль в кодировке Windows, а у тебя английская локаль (Cp1252, в ней нет кириллицы). Лечится `chcp 65001` в окне терминала или флагом `-Dstdout.encoding=UTF-8`. В IntelliJ и в выводе `mvnw` уже настроено. С аргументами ещё веселее: `java -cp out HelloClassic один два` превращает их в `????` и `???`, а лаунчер `java` в Windows раскрывает `?` как маску файлов — программа получает `.mvn`, `days`, `out`... Аргументы в терминале пока передавай латиницей.
8. **Аргументы с точкой в PowerShell — в кавычках.** `.\mvnw.cmd test -Dtest=day01.*Test` PowerShell разрежет на точке, и Maven получит мусор. Правильно: `"-Dtest=day01.*Test"`.

## Вопросы

Ответь сам, потом открой ответ.

**1. Чем JDK отличается от JVM?**

<details><summary>Ответ</summary>

JVM исполняет байткод — это «движок». JDK — полный набор для разработки: JVM + компилятор `javac` + стандартная библиотека + утилиты (`jshell`, `javap`, `jcmd`...). Чтобы только запускать программы, хватит JRE (JVM + библиотека, без компилятора), но для разработки нужен JDK.
</details>

**2. Что лежит в `.class` и почему один и тот же файл запускается и на Windows, и на Linux?**

<details><summary>Ответ</summary>

Байткод — инструкции для виртуальной машины, а не для конкретного процессора. Под каждую ОС есть своя JVM, она и переводит байткод в машинный код этой системы. «Написал один раз — запускай везде».
</details>

**3. Что даёт компиляция, если PHP прекрасно живёт без неё? Чем за это платим?**

<details><summary>Ответ</summary>

Даёт: ошибки типов, опечатки в именах методов, неверное число аргументов ловятся до запуска, а не на проде; IDE точно знает типы — автодополнение и рефакторинг надёжные; JIT быстрее интерпретатора. Платим: лишний шаг сборки, больше кода (типы везде), долгий старт JVM и «разогрев».
</details>

**4. Что значит каждое слово в `public static void main(String[] args)`?**

<details><summary>Ответ</summary>

`public` — доступен снаружи (JVM должна его вызвать); `static` — метод класса, а не объекта, вызывается без `new`; `void` — ничего не возвращает; `main` — имя, которое ищет JVM; `String[] args` — массив аргументов командной строки.
</details>

**5. Почему `java Hello.java` работает без `javac`, а в проектах так не делают?**

<details><summary>Ответ</summary>

Лаунчер `java` умеет сам скомпилировать исходник в памяти и сразу запустить — удобно для скриптов. Но компиляция повторяется на каждом запуске, а внешние библиотеки (jar) так подключать неудобно. Проект собирают один раз (Maven/Gradle) в `.class`/`.jar` и запускают готовое.
</details>

**6. Почему Java-сервер «разогревается», а PHP-FPM — нет?**

<details><summary>Ответ</summary>

JVM сначала интерпретирует байткод и только потом компилирует горячие методы JIT-ом, причём с оптимизациями по реальной статистике вызовов. Пока статистики нет — медленнее. PHP-FPM каждый запрос начинает заново (opcache кэширует только разобранный код), поэтому «разогреваться» ему нечему — но и ускориться за время работы он не может.
</details>

**7. Что такое classpath и на что из PHP он похож?**

<details><summary>Ответ</summary>

Список папок и jar-файлов, где JVM ищет классы по полному имени (`day01.Basics` → `day01/Basics.class`). Похоже на автозагрузку Composer по PSR-4, только JVM ищет сама по путям, без функции-автозагрузчика. Maven собирает classpath из зависимостей `pom.xml` автоматически.
</details>

## Практика

1. **Запусти оба Hello** из терминала (открой новое окно — старые не знают про `JAVA_HOME`). Добавь в `Hello.java` свою строку. Если вместо кириллицы `???` — см. грабли, пункт 7.
2. **Посмотри байткод** `HelloClassic` через `javap -c`. Найди строку «Привет...» и вызов `println`.
3. **Сломай компиляцию** — по одной ошибке за раз — и прочитай, что пишет `javac`:
   - убери `;` в конце строки;
   - напиши `String s = 'abc';`;
   - напиши `int x = "5";`.
4. **JShell:** посчитай `5 / 2`, `5 / 2.0`, `-3 % 2`, `Integer.MAX_VALUE + 1`. Последние два результата запомни — пригодятся в задачах.
5. **Открой проект в IntelliJ:** File → Open → `C:\projects\java-learning`. Проверь, что в File → Project Structure стоит SDK 25.
6. **Задачи:** `src/main/java/day01/Basics.java` — замени `throw new UnsupportedOperationException("TODO")` на решение, чтобы тесты `src/test/java/day01/BasicsTest.java` стали зелёными. Запуск — зелёная стрелка рядом с классом `BasicsTest` в IntelliJ или:

```powershell
.\mvnw.cmd test "-Dtest=day01.*Test"
```

   Тест со звёздочкой ★ — с подвохом. Если не получается — это нормально, он мостик ко дню 2.

<details><summary>Подсказка к isOdd</summary>

Вспомни, чему равно `-3 % 2`.
</details>

<details><summary>Подсказка к ★</summary>

Сколько будет `2_000_000_000 + 2_000_000_000` в `int`? Максимум `int` — около 2,1 миллиарда. Важно, в каком типе считается сумма — *до* того, как ты делишь на `2.0`.
</details>

7. **Запиши итог дня** в `progress.md` своей ветки: строку в журнал и пару заметок — что понял и что осталось непонятным. Потом закоммить и запушь (команды — в SETUP.md, раздел «Каждый день»).
